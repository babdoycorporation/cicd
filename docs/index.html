ReleaseRocket
Self-hosted Git hosting + CI/CD

ReleaseRocket gives your team a complete DevOps platform on your own servers — code review, issue tracking, and automated deployments without any external cloud dependency.

📁

Git Hosting

Browse code, view diffs, edit files in the browser, manage branches — all from the web.

🔀

Pull Requests

Code review with inline comments, approval rules, and merge protection.

🐛

Issue Tracker

Labels, milestones, and assignees. Close issues automatically from a PR description.

⚙️

CI/CD Pipelines

Builds trigger on every push. Logs stream live to any browser tab.

🖥️

Build Agents

Run builds on any Linux machine in your network — one Python file, no dependencies.

🔔

Notifications

In-app alerts for pipeline failures, PR reviews, mentions, and releases.

Getting Started

Quick Start

From zero to a running pipeline in about 10 minutes.

Log in

Navigate to your ReleaseRocket URL — typically http://your-server:8001. Enter the credentials your administrator provided, or click Sign up if self-registration is enabled.

Create a repository

1
Open the New Repository form

Click Repositories in the sidebar, then New Repository in the top-right corner.

2
Fill in the details

Name (lowercase letters and hyphens only, e.g. my-api), an optional description, visibility (Public or Private), and default branch name.

3
Create and clone

Click Create Repository. You land on the empty repo page. Copy the clone URL shown there.

Push your first commit

You need a Personal Access Token first — use it as the Git password.

bash
# Clone the new repository
git clone http://your-server:8001/git/username/my-repo.git
cd my-repo

# Add your files and commit
echo "# My Project" > README.md
git add .
git commit -m "Initial commit"

# Push — use your PAT when prompted for a password
git push origin main

Set up CI/CD

1
Add rockerci.yaml to your repo root

This file defines the build steps. See the Pipelines page for the full schema.

2
Create a Project → Application → Pipeline in the UI

Go to CI Dashboard → New Project, then create an Application and Pipeline inside it. Point the pipeline at your repository and branch.

3
Push — watch the build run live

Every push to the monitored branch triggers a run automatically. Click the run in the dashboard to watch logs stream in real time.

✓  You're set. Next, read Repositories to learn branching, in-browser editing, forking, and file uploads.
Getting Started

Core Concepts

A mental model of how ReleaseRocket is organized.

Repositories

A repository is a versioned store of files managed by Git. Every commit, branch, and tag lives here. Repos are stored as standard bare Git repositories on disk — fully compatible with any Git client.

Projects, Applications, and Pipelines

The CI/CD side uses a three-level hierarchy:

LevelDescriptionExample
ProjectTop-level grouping — one per product or teamAcme Platform
ApplicationA deployable service inside a projectauth-service, web-frontend
PipelineThe automated steps that run on code changesBuild → Test → Deploy

Build Agents

A build agent is any Linux machine (physical server, VM, or container) running linux_agent.py. When a pipeline triggers, the background worker dispatches the job to a free agent, which executes each step and streams output back in real time.

Personal Access Tokens

Instead of using your main password with Git or API scripts, you create a Personal Access Token (PAT). Tokens can be revoked any time without changing your password. They are stored as SHA-256 hashes — the raw value is shown once at creation only.

Organizations and Teams

Organizations group users and repositories under one umbrella (your company or department). Inside an org, Teams — e.g. Backend, DevOps — can be granted access to specific repositories.

Platform

Repositories

Create, browse, fork, and manage your code repositories.

Creating a repository

1
Navigate to Repositories → New Repository

Found in the left sidebar at any time.

2
Enter a name, description, and visibility

Name must be lowercase with hyphens (e.g. api-service). Visibility is Public (visible to all) or Private (collaborators only).

3
Click Create Repository

You land on the empty repo overview page with the clone URL displayed.

Browsing and editing code

The file tree lets you navigate directories and view files with syntax highlighting. Click any file's Edit (pencil) button to open the Monaco editor directly in the browser. Write a commit message and click Commit Changes — no local Git needed.

Uploading files

Click Upload File on the repository page, select files from your computer, add a commit message, and commit. Useful for assets or config files.

Cloning

bash
git clone http://your-server:8001/git/username/repo-name.git
# Enter your username and PAT when prompted

Forking

Click Fork on any repository page. Your fork appears in your own repository list. Changes you make to the fork don't affect the original until you open a pull request.

Branch protection

Prevent direct pushes to important branches and require a minimum number of PR approvals before merging. Configure at Repository → Settings → Branches → Protect a branch.

Platform

Pull Requests

Propose, review, and merge code changes through a structured team review workflow.

Opening a pull request

1
Push your feature branch

Your branch must exist on ReleaseRocket before creating the PR.

2
Open Pull Requests → New Pull Request

Inside the repository in the left sidebar.

3
Select source and target branches

Source = your feature branch. Target = the branch you want to merge into (usually main).

4
Write a title and description

Explain what changed and why. Add reviewers, labels, and a milestone if applicable.

5
Create (or Create as Draft)

Draft PRs can't be merged until you mark them ready for review.

Review types

ReviewWhat it means
ApproveCode is good. Counts toward the required approvals before merge.
Request ChangesAuthor must address feedback. Blocks merge until resolved.
CommentLeave feedback without approving or blocking.

Inline comments

Hover over any line in the diff and click the + icon that appears to leave a comment pinned to that exact line of code.

Merging

Once required approvals are met and no changes are requested, the Merge Pull Request button activates. Clicking it merges the source branch into the target and marks the PR as merged.

Issues & Milestones

Track bugs, tasks, and feature requests with structured labels and milestones.

Creating an issue

1
Go to Repository → Issues → New Issue

The Issues tab is in the repository navigation.

2
Write a clear title and body

Title: one-line summary. Body: full description, reproduction steps, screenshots.

3
Add labels, milestone, and assignees

Labels categorize the issue. Milestones group it into a sprint or release. Assignees are responsible.

4
Submit new issue

The issue is created, assigned a number, and appears in the issue list.

Auto-closing from a pull request

Include a closing keyword in any PR description. When the PR merges into the default branch, the referenced issue closes automatically.

PR description
Closes #42
Fixes #17, Resolves #88

Milestones

A milestone groups issues into a target — a sprint (Q3 Sprint) or a release (v2.0). Set a due date and track progress as a percentage bar (open vs. closed issues). View milestones at Repository → Milestones.

Platform

CI/CD Pipelines

Automate your build, test, and deploy workflow — triggered on every push.

The rockerci.yaml file

Drop this file in your repository root. It defines what runs every time someone pushes to a monitored branch.

rockerci.yaml
name: Build and Deploy

on:
  push:
    branches: [main, develop]

jobs:
  build:
    steps:
      - name: Install dependencies
        run: npm install

      - name: Run tests
        run: npm test

      - name: Deploy to production
        run: ./scripts/deploy.sh

Injected environment variables

Every step automatically receives these — no configuration needed:

VariableValue
CItrue
CI_COMMIT_SHAFull git commit hash
CI_BRANCHBranch name that triggered the run
CI_PROJECTProject name
CI_PIPELINEPipeline name
CI_RUN_IDUUID of this pipeline run

Add your own variables at Project → Configure → CI/CD Variables.

Build status reference

StatusMeaning
PendingQueued — waiting for a free build agent
RunningActively executing steps right now
SuccessAll steps exited with code 0
FailedOne or more steps returned a non-zero exit code

When a build fails

1
Open the failed run

Click the red run in the dashboard or build history.

2
Expand the failed step

Each step is collapsible. The failed step shows its full console output in red.

3
Fix and push — or re-trigger manually

A push to the monitored branch starts a new run automatically. Or click Trigger Build in the project to re-run without pushing.

⚠  If no agents are online, builds stay in Pending indefinitely. Check Dashboard → Agents to confirm at least one agent is live.
Platform

Access Tokens

Personal Access Tokens let Git clients and scripts authenticate without your main account password.

Creating a token

1
Go to Profile → Personal Access Tokens

Click your username in the bottom-left sidebar corner.

2
Enter a descriptive name

Name it by where you'll use it — laptop, deploy-script, vs-code. This helps when you need to revoke a specific one.

3
Click Generate Token and copy immediately

The raw token is shown exactly once. It is not stored on the server — only a SHA-256 hash is kept. If you lose it, delete and regenerate.

⚠  Copy your token before leaving the page. Once you navigate away, it cannot be retrieved.

Using a token with Git

bash
# Interactive prompt
git clone http://your-server:8001/git/username/repo.git
Username: your-username
Password: <paste token>

# Or embed in the remote URL for scripted use
git remote set-url origin \
  http://username:YOUR_TOKEN@your-server:8001/git/username/repo.git

Revoking a token

Click the trash icon next to any token on your Profile page. Revocation is instant — access using that token is denied immediately.

Local Setup

A running development environment in about 5 minutes.

Prerequisites

  • Python 3.11+
  • Git installed on the server machine
  • pip

Install and run

bash
# Clone and enter the project
git clone <url> releaserocket
cd releaserocket/cicd_tool

# Virtual environment
python -m venv .venv
source .venv/bin/activate

# Dependencies
pip install django gitpython pillow

# Environment variables (minimum required)
export DJANGO_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(50))')"
export REPO_BASE_PATH="/tmp/releaserocket/repos"
export CI_RUNS_DIR="/tmp/releaserocket/ci-runs"
mkdir -p $REPO_BASE_PATH $CI_RUNS_DIR

# Database
python manage.py migrate
python manage.py createsuperuser

# Start
python manage.py runserver 0.0.0.0:8001

Developer Guide

Pipeline Engine

How the background worker dispatches and executes CI/CD runs.

Execution flow

1
PipelineRun created with status pending

Triggered by a git push to a monitored branch, or a manual trigger from the UI.

2
Worker polls the database every 10 seconds

start_pipeline_worker() runs as a daemon thread started in PipelineConfig.ready().

3
Agent selected and marked is_busy=True

First available agent where live=True and is_busy=False.

4
Thread spawned: _execute_run(run_pk, agent_pk)

Each step in rockerci.yaml is sent via POST to the agent's HTTP server. stdout streams back line-by-line into PipelineStep.log.

5
Run finishes — notifications dispatched

PipelineRun.status set to success or failed. Agent marked is_busy=False.

Starting a build agent

bash
python linux_agent.py \
  --server http://releaserocket-host:8001 \
  --port 9000 \
  --hash-key "your-secret-hmac-key"

Then register it in the UI at Dashboard → Agents → Add Agent using the same host, port, and hash key.

Developer Guide

Git HTTP Protocol

How ReleaseRocket implements Git Smart HTTP for clone, fetch, and push.

Overview

The GitService class-based view implements the full Git Smart HTTP transfer protocol. Repositories are stored as bare git repos at REPO_BASE_PATH/<owner>/<repo>.git.

Endpoints

MethodURLPurpose
GET/git/<owner>/<repo>.git/info/refs?service=git-upload-packClone/fetch negotiation
POST/git/<owner>/<repo>.git/git-upload-packSend pack objects (clone/fetch)
GET/git/<owner>/<repo>.git/info/refs?service=git-receive-packPush negotiation
POST/git/<owner>/<repo>.git/git-receive-packAccept pushed objects

Post-push actions

After a successful push, the view updates Branch and Commit records, logs an ActivityEvent, and — if a Pipeline monitors the pushed branch — creates a new PipelineRun with status pending.

Developer Guide

Auth & Security

Session auth for the web UI, PAT hashing for Git, HMAC for agent communication.

Token hashing

python
import hashlib, secrets

@classmethod
def create_token(cls, user, name):
    raw = secrets.token_urlsafe(40)
    instance = cls.objects.create(
        user=user, name=name,
        prefix=raw[:8],                      # display only
        token_hash=hashlib.sha256(raw.encode()).hexdigest()
    )
    return instance, raw  # raw returned once, then gone

Agent authentication

The pipeline worker signs every HTTP request to build agents with HMAC-SHA256 using the agent's hash_key. Agents reject any request with an invalid signature, preventing unauthorized job injection even if the agent port is accidentally exposed.

Branch protection enforcement

BranchProtectionRule is checked server-side in PullRequest.can_merge(user) — not just hidden in the UI. If required approvals are not met, the merge endpoint returns an error regardless of how the request was made.

Production Deployment

Gunicorn + Nginx on a Linux server — recommended setup.

Gunicorn

bash
gunicorn cicd_tool.wsgi \
  --workers 4 \
  --bind 0.0.0.0:8001 \
  --timeout 120 \
  --keep-alive 5

Nginx — critical SSE config

nginx
server {
    listen 443 ssl http2;
    server_name git.example.com;
    client_max_body_size 500M;

    location /static/ { alias /var/www/releaserocket/static/; }
    location /media/  { alias /var/www/releaserocket/media/; }

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Required for live build log streaming (SSE)
        proxy_buffering    off;
        proxy_cache        off;
        proxy_read_timeout 300s;
    }
}
⚠  proxy_buffering off is not optional. Without it, Nginx buffers the SSE stream and live build logs appear only after the connection closes.

systemd service

systemd unit
[Unit]
Description=ReleaseRocket
After=network.target postgresql.service

[Service]
User=releaserocket
WorkingDirectory=/opt/releaserocket/cicd_tool
EnvironmentFile=/opt/releaserocket/.env
ExecStart=/opt/releaserocket/.venv/bin/gunicorn \
  cicd_tool.wsgi -w 4 -b 0.0.0.0:8001
Restart=always

[Install]
WantedBy=multi-user.target
