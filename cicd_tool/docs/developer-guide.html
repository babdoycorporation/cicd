System Overview

ReleaseRocket is a self-hosted, open-source DevOps platform combining Git repository hosting, pull request workflows, issue tracking, and a CI/CD pipeline execution engine — all in a single Django application. It is designed to replace external dependencies on GitHub, GitLab, and Jenkins for teams that require on-premises control.

Authentication & Security

Web UI Authentication

Standard Django session authentication. All views are protected with @login_required. CSRF middleware is enabled on all POST endpoints.

Git HTTP Authentication

Git push/clone over HTTP uses HTTP Basic Auth. The GitService class-based view intercepts the Authorization header and validates credentials against PersonalAccessToken:

# Secure token verification flow
def _authenticate(self, request, repository):
    auth = request.META.get('HTTP_AUTHORIZATION', '')
    # Decode Basic Auth header
    username, password = base64.b64decode(auth[6:]).decode().split(':', 1)
    token_hash = PersonalAccessToken.hash_token(password)
    # Constant-time comparison via DB lookup
    token = PersonalAccessToken.objects.filter(
        user__username=username,
        token_hash=token_hash,
        expires_at__gt=now()   # or expires_at is None
    ).first()
    return token is not None
⚠️ Token Storage Policy

Raw tokens are never stored. Only the SHA-256 hash is persisted. The raw token is shown exactly once at creation time. Tokens can optionally have an expiry date.

Agent Security

Each Agent record stores a hash_key. All commands sent to linux_agent.py must include an HMAC-SHA256 signature in the X-Hash-Key header. Agents can optionally use TLS (pass --ssl-cert / --ssl-key).

CI/CD Pipeline Engine

Execution Flow

  1. Trigger: A build is triggered via the UI (Trigger Build button) or automatically when a push arrives on a monitored branch. A PipelineRun record is created with status='pending'.

  2. Worker polling: pipeline/worker.py runs in a daemon thread, polling every 10 seconds for pending runs. It calls get_available_agent() to find an online, non-busy agent.

  3. Dispatch: The agent is marked is_busy=True. A new thread is spawned per run calling _execute_run(run_pk, agent_pk).

  4. Step execution: execute_step() in utils.py sends each YAML-defined step to the agent via its HTTP API, streaming stdout back and writing to PipelineStep.log.

  5. Completion: PipelineRun.status is set to success or failed. The agent is released (is_busy=False). Notifications are sent if enabled.

rockerci.yaml Format

name: Build and Deploy
on:
  push:
    branches: [main, staging]

jobs:
  build:
    steps:
      - name: Install dependencies
        run: npm install
      - name: Run tests
        run: npm test
      - name: Build Docker image
        run: docker build -t myapp:$CI_COMMIT_SHA .
      - name: Deploy

Git HTTP Smart Protocol

The GitService CBV in gitmgmt/views.py implements the full Git Smart HTTP protocol, enabling any standard Git client to clone, fetch, and push using the hosted repositories.

# Clone a repository
git clone http://localhost:8001/git/alice/my-repo.git

# Push using a Personal Access Token
git remote set-url origin http://alice:<PAT>@localhost:8001/git/alice/my-repo.git
git push origin main

The server stores bare repositories under REPO_BASE_PATH (configured via env var, default /repos). On a git-push, the server updates the Commit, Branch, and ActivityEvent records and triggers any pipelines watching the pushed branch.

Local Development Setup

# 1. Clone and enter the project
git clone <repo-url> releaserocket
cd releaserocket/cicd_tool

# 2. Create virtual environment
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install django gitpython pillow

# 4. Set required environment variables
export DJANGO_SECRET_KEY="dev-secret-change-in-production"
export REPO_BASE_PATH="/tmp/repos"
export CI_RUNS_DIR="/tmp/ci-runs"

# 5. Run migrations
python manage.py migrate

# 6. Create superuser
python manage.py createsuperuser

# 7. Start development server
python manage.py runserver 0.0.0.0:8001
Migration Note

If you see "conflicting migrations", run python manage.py makemigrations --merge then migrate again. This resolves the merge migration between the auto-generated initial and the new-models migration.

Nginx Config Snippet

server {
    listen 443 ssl;
    server_name git.example.com;

    # Allow large git push payloads
    client_max_body_size 500M;

    location /static/ { alias /var/www/releaserocket/static/; }
    location /media/  { alias /var/www/releaserocket/media/; }

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # Required for SSE (Server-Sent Events) log streaming
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }
}
⚡ SSE / Streaming

Set proxy_buffering off in nginx. Without this, live pipeline log streams will not reach the browser until the response is fully buffered.

Contributing Guidelines

Branch Strategy

BranchPurpose
mainProduction-ready releases only
developIntegration branch for features
feature/<name>New features — branch from develop
fix/<name>Bug fixes — branch from develop or main

Adding a New Feature Checklist

  1. Add the Django model in models.py with proper FKs, Meta.ordering, and __str__.

  2. Run python manage.py makemigrations <app> and review the generated migration.

  3. Add the view function in views.py decorated with @login_required. Use get_object_or_404 for lookups.

  4. Register the URL in urls.py with a named pattern (name='...') so templates can use {% url %} tags.

  5. Create a template that extends pipeline/base.html and uses CSS variables (var(--card-bg), etc.) for the dark theme.

  6. Register the model in admin.py with appropriate list_display and search_fields.

  7. Write a log_activity() or notify() call for significant user actions so they appear in the activity feed.

Code Style

Follow PEP 8. Use Django ORM queries rather than raw SQL. Template logic should be minimal — move business logic into model methods or view helpers. All new URL names should use hyphens, not underscores (e.g. pipeline-detail not pipeline_detail).
